# 邮件功能修复总结

## 问题分析

原始问题：
1. 邮件配置API获取的是第一条记录而不是最新记录
2. 测试邮件失败，因为使用了测试用的虚拟配置（test@gmail.com）
3. 发件人地址与认证用户不匹配，导致企业邮箱发送失败
4. 邮件配置界面只支持部分服务商

## 修复方案

### 1. 修复数据库查询逻辑
**文件：**
- `src/app/api/email/config/route.ts`
- `src/app/api/email/test/route.ts`
- `src/app/api/auth/send-login-code/route.ts`
- `src/app/api/auth/forgot-password/route.ts`

**修改：**
```sql
-- 修改前（获取第一条记录）
SELECT * FROM email_configs WHERE id = 1

-- 修改后（获取最新记录）
SELECT * FROM email_configs ORDER BY updated_at DESC, created_at DESC LIMIT 1
```

### 2. 修复发件人地址设置
**文件：**
- `src/lib/email.ts`
- `test-email.js`

**修改：**

// 修改前（固定发件人）

## 邮件服务商配置参考

### Gmail
- SMTP服务器: smtp.gmail.com
- 端口: 587
- 安全连接: 否
- 要求: 开启两步验证，使用应用专用密码

### QQ邮箱
- SMTP服务器: smtp.qq.com
- 端口: 587
- 安全连接: 否
- 要求: 开启SMTP服务，使用授权码

### 163邮箱
- SMTP服务器: smtp.163.com
- 端口: 465
- 安全连接: 是
- 要求: 开启SMTP服务，使用客户端授权密码

### 企业邮箱
- SMTP服务器: 根据服务商配置
- 端口: 25或587或465
- 安全连接: 根据服务商要求

## 注意事项

1. **企业邮箱限制** - 部分企业邮箱只能发送给同域名邮箱
2. **授权码/应用密码** - 不要使用登录密码，使用专用授权码
3. **网络访问** - 确保服务器可以访问SMTP服务器
4. **安全连接** - 465端口通常需要SSL，587端口使用STARTTLS
